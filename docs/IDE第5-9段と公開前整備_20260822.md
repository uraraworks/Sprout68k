# Sprout68k IDE 第5〜9段と公開前整備の記録 2026-08-22

## 範囲

IDE第4段以後、公開前までに追加・修正した内容を記録する。ブラウザでの実測は
Chromium系1種で行った。Safari / Firefox、GitHub Pages上の公開版は未実測である。

## IDE第5〜9段

### 第5段: コンパイル診断の日本語注釈

本家のcc1 / ldへ故障コードを実際に入力して採取した14種類のメッセージを基準に、
GCC / ld原文を消さず「何が起きたか」「次にすること」を別枠で表示する層を追加した。
未知の診断は原文のまま通す。規則の詳細は
[`コンパイル診断注釈_20260822.md`](コンパイル診断注釈_20260822.md)に記録した。

### 第6段: 1クリック復帰

停止と既知の成功XDFを再起動する導線を作り、その後UI整理で実行／停止トグルへ統合した。
現在は実行のたびに既存ホストを止め、`runFresh()`から新しいエミュレータを生成する。
暴走した実行状態を引き継がず、保存済み・未保存の編集中ソースは1バイトも変更しないことを
検証している。

### 第7段: キーボード入力

カーソル4方向、Space、Enter、Esc、英字、数字の9種類について、押下と解放がゲスト画面へ
届くことを実測した。ホストのキーボードに直接対応がないX68000のキー10種類は棚卸しし、
未対応であることを明記した。詳細は
[`IDEキーボード入力_20260822.md`](IDEキーボード入力_20260822.md)を参照。

### 第8段: Service Workerとオフライン配布

公開物からprecache一覧を生成し、URL・サイズ・SHA-256を検証するService Workerを追加した。
Chromium系ブラウザ1種で、オンライン時に準備した後サーバーを停止し、再読込して
書く→ビルド→実行まで通ることを確認した。設計と実測は
[`IDE配布設計_20260822.md`](IDE配布設計_20260822.md)に記録した。

### 第9段: wasmツールのRelease配布経路

約20MBのmemfs版ツール8ファイルを決定的archiveにし、sidecar manifest、archive、展開後の
各ファイルを検証してからPagesを組み立てる経路を用意した。リモート、Release、Pagesは
未作成であり、実際の公開はまだ行っていない。手順は
[`Release配布手順_20260822.md`](Release配布手順_20260822.md)を参照。

## 公開前の整備

- 仮称から製品名をSprout68kへ確定し、芽吹きを表すふたばのアイコンを作成した。
- `CONTRIBUTING.md`、Issue Forms、PRテンプレートを公開前に配置した。受け取れる情報の
  基準を「エミュレータや実機で自分で測れば同じ結果が得られる種類の情報か」とした。
- 日英を1ファイルに収めた `ide/help.html` を追加し、アプリ内から別タブで開く導線、
  UIラベルとの機械照合、公開物・precacheへの収録を検証した。
- ツールバーを整理し、中心操作のビルドと実行だけをアイコン＋文字にした。実行／停止は
  状態でラベル、アイコン、アクセシブル名、ツールチップが切り替わる1ボタンに統合した。
- エディタと実行画面にスプリットバーを設け、比率をlocalStorageへ保存した。実行画面は
  アスペクト比を保ったまま中身も拡大する。
- サンプルの不要な停止ループを削除し、Google C++ Style Guideに沿う形へ整理した。
  公開APIのsnake_caseは変更せず、サンプル定義の関数・定数と役割を見分けられるようにした。
- ブロック崩しは二重描画と速度を修正し、フレームバッファのブロック数・配置とホスト側の
  フレーム進行を機械検査した。

## 踏んだ罠

### SVG子要素では`hidden`属性に頼れない

- **症状**: 実行／停止トグルの再生アイコンと停止アイコンが重なって同時に見えた。
- **真因**: HTMLのUAスタイルシートによる`[hidden]`の非表示が、SVGの子要素には適用されず、
  両方が描画されていた。
- **どう気づいたか**: 実ブラウザで重なりを確認し、各SVG子要素の算出`display`を測ると、
  `hidden`付きの要素も描画対象だった。
- **再発防止**: ボタン状態を`data-state`で表し、CSSの`display: none`で排他表示する。
  検査も属性の有無ではなく算出される`display`を判定し、同時表示の故障注入を置いた。

### 選択レイヤーが現在行の背景に隠れた

- **症状**: 複数行の選択は見えるが、カーソルのある1行だけを選択すると選択色が消えた。
- **真因**: CodeMirror 6の選択レイヤーは`z-index: -2`で、通常フローの不透明な現在行背景が
  その上を完全に覆っていた。
- **どう気づいたか**: 選択要素は存在するのに見えなかったため、選択レイヤー、選択矩形、
  現在行の`position`、`z-index`、背景色を算出スタイルで並べ、重なり順を確定した。
- **再発防止**: 現在行色を半透明にした。検査は要素の存在ではなく、選択色へ現在行色を
  重ねた最終合成色の色差・コントラストを計算し、不透明化の故障注入を拒否する。

### ViteのbaseがHTML参照へ二重に付いた

- **症状**: devサーバーでロゴ、favicon、manifestのURLが`/Sprout68k/Sprout68k/`から始まり、
  404になった。従来検査はPASSしていた。
- **真因**: HTML側に公開base込みの絶対パスを書き、Viteもbaseを付与していた。検査は参照先と
  同名のファイルがディスクにあることしか見ず、ブラウザのURL解決を再現していなかった。
- **どう気づいたか**: 実ブラウザでHTMLの全参照URLをfetchし、4件の404と二重接頭辞を得た。
- **再発防止**: HTMLは相対参照とし、dev変換後とdistのHTMLをそれぞれbase込みでURL解決して
  公開物へ対応づける。二重baseを再注入すると落ちる検査を置いた。

### Service Workerを通らない取得経路があった

- **症状**: オフライン再読込でHTMLは出るが、初期module、preload、CSS、のちにはentryだけが
  失敗した。
- **真因**: Chromiumの先読み要求は制御確定前に走り、dynamic importのmodule loaderも
  この再読込条件ではService Workerのfetchへdispatchされなかった。
- **どう気づいたか**: 同じURLを明示`fetch`すると成功し、失敗要求だけ`workerStart=0`だった。
  entryの取得方法だけがnative importであることまで比較して切り分けた。
- **再発防止**: 起動資産を制御確定後の明示fetchへ統一し、静的依存をBlob URLへ置換してから
  entryをimportする。キャッシュだけで依存閉包を組めることも検査する。

### precacheが空でも既存workerはactivatedのまま残る

- **症状**: cacheを消して再登録しても`installing`と`waiting`がなく、`active=activated`のまま、
  precacheが空だった。
- **真因**: cache削除は同じscriptのinstallを再実行しない。unregister後も制御中clientがあれば
  active workerは生存し、直後の再登録で再利用され得る。
- **どう気づいたか**: workerの状態とcache件数を同時に測り、install失敗ではなくinstall自体が
  走っていないことを確認した。
- **再発防止**: activate、IDE起動、fetch miss、online復帰時に全件を再検証して不足を補う。
  完了まで「準備中」、成功時だけ「オフラインでも使えます」、失敗時は赤表示にする。

### ブロック崩しでブロック列が横に二重描画された

- **症状**: ボールとパドルは1つだが、ブロック列だけが画面右側へ重複した。
- **真因**: 前の画面設定からCRTCの表示幅が残留し、起動時に現在モードの表示幅を明示設定して
  いなかった。ビルド経路の差ではなかった。
- **どう気づいたか**: IDE利用者ターゲットと正典XDFのバイト一致でビルド差を除外し、Nodeの
  px68kでも再現した。フレームバッファの左右パターンとCRTC設定を突き合わせて確定した。
- **再発防止**: 起動時に表示幅を明示設定する。フレームバッファからブロック数32、右側の
  重複0を測り、旧設定を戻す故障注入を拒否する。

### ブロック崩しが遅かった

- **症状**: 操作してもゲームの進行が実時間に対して著しく遅かった。
- **真因**: 変化しない32個のブロックまで毎ループ描き直し、描画処理が1フレームの大半を
  占めていた。当たり判定や入力が主因ではなかった。
- **どう気づいたか**: ゲストへ計測コードを足さず、ホスト側でフレーム数と実時間を数え、
  描画・当たり判定・入力を分離して比較した。
- **再発防止**: 静止ブロックは初期描画と破壊時だけ更新する。旧描画を戻した前後でホスト側の
  フレーム進行を比較する速度検査を残した。
