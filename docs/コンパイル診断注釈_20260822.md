# コンパイル診断の日本語注釈 実測記録 2026-08-22

## 方針

入門者が起こしやすい誤り14種類と、未知診断の素通し確認1種類を
`tools/diagnostic-cases/` に独立したCソースとして置いた。注釈文や一致規則を作る前に、
次のコマンドでIDEと同じmemfs版cc1を実行した。`main`誤記だけは既存の `user` builderで
ldまで進めた。

```sh
node tools/driver/collect_diagnostics.mts
```

以下の「採取した診断」は、この実行で得たGCC 13.4.0 / GNU ld 2.44の文面である。
開発機固有の絶対パスだけを除き、ファイル名・行・桁・severity・メッセージ本文は変更して
いない。ソース本文は表からリンクした各 `.c` が一次情報である。

GCC / ld原文欄にそのまま残す。採取時に同じ誤りから追加で出た診断行は次のとおり。

```text
01_missing_semicolon.c:3:10: error: expected statement before ')' token
02_missing_parenthesis.c:5:1: error: expected expression before '}' token
04_undeclared_variable.c:2:3: note: each undeclared identifier is reported only once for each function it appears in
06_integer_to_pointer.c:2:9: warning: variable 'message' set but not used [-Wunused-but-set-variable]
09_too_few_arguments.c:1:12: note: declared here
10_wrong_argument_type.c:1:38: note: expected 'const char *' but argument is of type 'int'
m68k-elf-ld: warning: user.elf has a LOAD segment with RWX permissions
13_missing_return.c:2:7: warning: unused variable 'score' [-Wunused-variable]
14_unterminated_string.c:2:25: warning: missing terminating " character
14_unterminated_string.c:3:3: error: void value not ignored as it ought to be
```

## 予想と違った実出力

- `;`忘れの主診断は単純な `expected ';'` ではなく、宣言の直後では
  `expected ',' or ';' before 'for'` だった。さらに同じ `for` から
  `expected statement before ')' token` も続いた。
- 戻り値のない関数は `control reaches end of non-void function` ではなく、今回のcc1では
  `no return statement in function returning non-void` だった。
- `mian`はcc1では警告にならず、ldで初めて `undefined reference to 'main'` になった。

## 規則、原文保持、衝突処理

規則は `tools/driver/diagnostic_annotations.mts` に置き、上表で採取した英語句だけへ限定して
いる。診断全文は `original` として1文字も変更せず保持し、日本語注釈は別の配列として返す。
IDEは「GCC / ld 原文」と「日本語の説明」を別枠で表示する。注釈にはエラー／警告と、取得
できる場合はファイル・行・桁を表示し、「何が起きたか」「次にすること」を分ける。

全規則を照合してspecificityが最大の1件だけを採用する。より限定的な文面の規則ほど値を
大きくしている。同じ規則・同じ位置でwarningとerrorが連続した場合はerror側1件にまとめる。
実測コーパスの全診断行について一致規則数を機械的に数え、2件以上の一致が0件であることも
検証する。未知診断には何も足さない。

未知診断用ソース [`99_unknown_pragma_error.c`](../tools/diagnostic-cases/99_unknown_pragma_error.c)
の実出力は次であり、注釈なしで原文だけを返した。

```text
99_unknown_pragma_error.c:1:2: error: #error X68KDEV_RARE_DIAGNOSTIC_9173
    1 | #error X68KDEV_RARE_DIAGNOSTIC_9173
      |  ^~~~~
```

## 検証

```sh
node tools/driver/verify_diagnostic_annotations.mts
```

14種類すべてを毎回実cc1/ldへ通し、原文保持、期待規則、未知診断の素通し、severity、規則
衝突を検査する。確定結果は **14種類中14種類に注釈、未知1種類は注釈0、衝突0件**だった。

注釈規則を検査上だけ無効化する陽性対照:

```sh
X68KDEV_DIAGNOSTIC_ANNOTATION_FAULT=1 node tools/driver/verify_diagnostic_annotations.mts
```

`missing_semicolon: 期待する注釈が実診断に付きませんでした`を検出し、終了コード1になった。
製品コードには注釈を無効化する設定はない。
