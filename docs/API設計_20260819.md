# 学習用 API 第一版 設計 20260819

## 位置づけ

Stage A〜D でブート経路・C 実行・ディスク全体ロード・実機互換が実測で通った。
次は構想（`../../docs/構想_20260819.md`）の必須要件 (c)「学習用 API は範囲外を
無視して落ちない設計」を担う層を作る。

## 2層に分ける

- **L0（生層）**: 実測済みの事実そのまま。GVRAM/CRTC/VC 直書き、IOCS 直呼び。
  上級者と、L1 の実装自身が使う。
- **L1（学習層）**: 入門者が触るのはここだけ。以下の原則を守る。

### L1 の設計原則

1. 座標・色・添字は**すべてクリップ/丸め**。エラーコードを返さない
   （返しても入門者は見ない。「何も起きない」で済ませる）
2. **ポインタを露出しない**。値と配列だけで書けるようにする
3. **暴走は「静かに固まる」ではなく「見える形で止まる」**。例外ベクタを埋め、
   日本語のパニック画面を出す。要件 (a) 1クリック復帰・(b) エラーの日本語注釈と
   噛み合わせる
4. **API は最初の作例から逆算して削る**。網羅から入ると、測っていない機能の
   宣言だけが増える

## 基準にする作例: ブロック崩し

構想の発端（あうぇっど氏の投稿の題材）と同じ。矩形塗り・当たり判定・キー入力・
フレーム同期で成立し、スプライトも音源も要らない。第一版の API はこれに要る
機能だけとする。

## 画面モード: 65536色1ページ固定 + 裏バッファ

Stage B で実測済みのモード（CRTC R20 bit3 + VC R0 下位2bit=3 + VC R2）をそのまま
使う。裏画面をメインメモリに持ち、垂直同期のタイミングで GVRAM へ転送する。

- 利点: 実測済みの経路から出ない。色数・パレットの概念を入門者に説明しなくてよい
- **リスク(実測済み・2026-08-19、再測定で訂正済み)**: 転送方式によって結果が
  異なることを確認した。word/long単位のCPUコピーでは全画面(512KB)は1フレームに
  収まらない(word: 約6.4フレーム=全画面の約15.6%、long: 約3.2フレーム=約31.2%)。
  movem(`MOVEM.L`一括転送)方式では1フレーム未満(約0.38フレーム、全画面の
  約2.6倍相当)で収まる実測値が出たが、この数値をサイクルタイミングへ換算すると
  68000として物理的にあり得ない値になる不整合が見つかっており、精度は未確定
  (詳細: `docs/StageE-2-3_実測_20260819.md`)。差分転送・16色4ページ方式それぞれの
  判断材料は実測資料に記載した。**後退の判断は実測後に行い、それまで API の形は
  変えない**(どちらへ後退するかはこの資料では決めていない)

## 第一版 API（案）

未実測の項目に依存する部分は「Stage E で確定」と明記する。関数名は仮。

### 画面

| 宣言 | 挙動 |
|---|---|
| `void screen_open(void);` | 65536色1ページモードを設定し裏バッファを用意する |
| `void screen_flip(void);` | 垂直同期を待ち、裏バッファを GVRAM へ転送する |
| `void cls(int color);` | 裏バッファ全体を塗る |
| `void pset(int x, int y, int color);` | 範囲外は無視（何もしない） |
| `int  pget(int x, int y);` | 範囲外は 0 を返す |
| `void box_fill(int x, int y, int w, int h, int color);` | 画面外にはみ出す分はクリップ。w/h が負なら何もしない |
| `void box(int x, int y, int w, int h, int color);` | 枠のみ |
| `void line(int x1, int y1, int x2, int y2, int color);` | 両端とも画面外でも落ちない |
| `int  rgb(int r, int g, int b);` | 0〜255 を受け、範囲外は丸めて 16bit 色値を返す |

画面サイズ定数（`SCREEN_W` / `SCREEN_H`）は **Stage E-1 で実測により確定した**
（詳細: `docs/StageE-1_実測_20260819.md`、検証コード: `verify/verify_e1.mts`）。

- `SCREEN_W = 512`（GVRAM 1ライン = 512 ワード = 1024 バイト。stride を全数対応表から実測）
- `SCREEN_H = 512`（y=511 まで可視、y=512 は不可視であることを実測）
- GVRAM オフセット0はフレームバッファ上の (0,0) に出る（原点のずれ無し）

Stage B で読んだ 768x512 は px68k のフレームバッファ（canvas）側の寸法であり、
65536色1ページの GVRAM 論理サイズ（512x512）とは別物だった。65536色グラフィック面は
canvas の左側512ドットぶんのみを占める。

### 文字

| 宣言 | 挙動 |
|---|---|
| `void print(const char *s);` | 現在位置に表示（IOCS $21。実測済み） |
| `void print_at(int col, int row, const char *s);` | 座標指定。**座標指定の手段は Stage E-6 で確定** |

### 入力（すべて Stage E-4 で確定）

| 宣言 | 挙動 |
|---|---|
| `int key_down(int key);` | 押されている間ずっと真。ブロック崩しのパドルに要るのは押しっぱなし判定なので、1回読むと消える入力ではなくビットセンス側が本命 |

キー定数（`KEY_LEFT` 等）は実測で確定した値だけを定義する。

### 時間

`screen_flip()` が垂直同期待ちを兼ねるため、第一版では独立した待ち関数を置かない。
必要性が出たら追加する。

### 乱数

| 宣言 | 挙動 |
|---|---|
| `void rand_seed(unsigned int seed);` | 種を設定 |
| `int  rand_int(int n);` | 0〜n-1 を返す。`n <= 0` なら 0 を返す（ゼロ除算で落とさない） |

### 音

第一版では**出さない**。構想で「新規作業として重いもの」に分類済み
（MXDRV/ZMUSIC は Human68k 常駐前提で使えない）。

## 落ちない代わりに「見える形で止まる」

例外ベクタを全部埋め、アドレスエラー・不正命令・ゼロ除算で日本語の停止画面を
出す。表示するのは「何が起きたか」と PC の値まで。ここが要件 (a) の1クリック
復帰の入口にもなる。

**実現可能性は Stage E-5 で実測する**（ベクタを書き換えて実際に捕まえられるか）。

## API を書く前に測る項目（Stage E）

**API の宣言を書く前にこれらを実測する。** 過去に「手読みを実測済みと称して
渡し、IOCS $46 の転送先レジスタを誤った」実績があるため、以下はすべて
**実際に px68k 上で動かして確かめる**こと。解読と実測は出所を分けて記録する。

| # | 項目 | 合格条件 |
|---|---|---|
| E-1 | 65536色1ページの GVRAM 論理サイズと1ライン当たりのバイト数 | **実測済み(2026-08-19)**。stride=512ワード(1024バイト)、SCREEN_W=512、SCREEN_H=512、原点ずれ無し。全数対応表・陰性対照・入力追従・色潰れの自己故障注入まで実施(詳細: `docs/StageE-1_実測_20260819.md`) |
| E-2 | 垂直同期の検出方法と1フレームの実時間 | **実測済み(2026-08-19)**。MFP GPIP($E88001) bit4 の立下りエッジ検出を確定。同期待ちN回とhost側フレーム数の比=1.0000(300/300)、陰性対照(同期待ち無し)は比が7852倍に崩れることを確認(詳細: `docs/StageE-2-3_実測_20260819.md`) |
| E-3 | 裏バッファ→GVRAM 転送が1フレームに収まるか | **実測済み(2026-08-19、再測定で訂正済み)**。word/long方式(CPUコピー)は512KB(全画面)が1フレームに収まらない(全画面の約15.6%/約31.2%)。movem方式(`MOVEM.L`一括転送)は1フレーム未満で収まる実測値(約2.6倍相当)が出たが、サイクル数換算で68000として物理的にあり得ない値になる不整合が見つかっており精度は未確定。ポーリング間隔の収束確認はN=4096でも未収束(ポーリング負荷が残っている状態の実測値)。後退案(差分転送/16色4ページ)の判断材料まで記録(決定はしていない。詳細: `docs/StageE-2-3_実測_20260819.md`) |
| E-4 | キー入力（押しっぱなし判定を含む）のレジスタ規約 | 押下・離鍵の両方が末端で観測できること。定数の一致ではなく、押した結果が画面に出るところまで通す |
| E-5 | 例外ベクタを書き換えて実際に捕捉できるか | わざと不正アクセスを起こし、停止画面が出ること。**故障注入して初めて合格**とする |
| E-6 | 文字表示の座標指定の手段 | 指定した座標に出ること。座標を変えると位置が追従すること |

各項目とも、**陰性対照または故障注入を1つ添えてから合格とする**。検査が空振り
していないことを先に確かめる（Stage B の判定が空振りしていた実績があるため）。
