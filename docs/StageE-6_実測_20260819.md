# Stage E-6 実測 20260819

学習用 API `print_at(col, row, s)`(座標を指定して文字列を表示する)を実装するための
手段を実測した。手読みの候補と実測で確認した事実は出所を分けて記録する。

## 結論

### 確定した座標指定の手段

- **候補の出所(解読)**: `datacrystal.tcrf.net` の `X68k/IOCS` ページを WebFetch で
  読んだ内容。「B_LOCATE」が D0=`$23`、D1.W=桁位置(X)、D2.W=行位置(Y)、
  「D1.W=-1 のときは現在位置の取得のみ」と記載されていた。**このリポジトリでは
  IOCS $46 の転送先レジスタを手読みで誤り(A0と誤読、実際はA1)、実測で発覚した
  実績がある**ため、この候補もそのままでは「実測済み」として扱わなかった。
- **実測で確認した事実**: D0=`$23`, TRAP #15(D1.L=col, D2.L=row。呼び出し規約は
  D1.W/D2.Wとの手読みだが、Cの`int`は32bitで符号拡張済みのためD1.L/D2.Lを渡して
  差し支えない)を呼んだ後に IOCS $21(Stage A/Cで実測済みの文字列表示)を呼ぶと、
  **指定した桁・行に、指定した文字列がそのまま表示される**ことを4箇所で実測した
  (詳細は下記)。候補は実測で裏付けが取れた。
- 実装は `stage_e/src/iocs_e6.S` の `iocs_locate(int col, int row)`。**D2 は
  m68k SVR4 ABI(gccの前提)で callee-saved のレジスタであり、これを退避せずに
  破壊すると呼び出し元(main関数のループ変数等)を無言で壊す。** 実装の最初の版で
  これを踏み、4箇所中3・4箇所目のマーカーが理由もなく画面から消える症状が出た
  (`git log` 上は残っていないが、このセッション内で実際に踏んだ)。IOCS呼び出し
  自体の規約とは別の、Cの呼び出し規約(ABI)由来のバグである点を記録しておく。

### 4箇所の実測結果(入力追従)

`stage_e/src/main_e6.c` + `tools/build_stage_e6.sh` + `verify/verify_e6.mts` で、
左上・右寄り・下寄り・中央の4箇所に別々の文字列を表示し、`readTextScreen()` の
該当行・該当列に指定通りの内容が現れることを実測した(px68k、`no_wait_mode=enabled`、
`ramsize=1MB`、`cpuspeed=16Mhz`)。

| 文字列 | 指定(col, row) | 実測結果 |
|---|---|---|
| `TOPLEFT` | (2, 1) | 一致 |
| `RIGHTSIDE` | (70, 3) | 一致 |
| `BOTTOM` | (5, 28) | 一致 |
| `CENTER` | (48, 16) | 一致 |

4箇所すべてで指定した座標に指定した文字列がそのまま出ることを確認した
(`RESULT: E6_PRIMARY_FOUR_POINTS_OK=true`)。

### 陰性対照(座標指定なし)

同じ4文字列を `iocs_locate()` を呼ばずに `iocs_print()` だけで出すと、
先頭から連続して `TOPLEFTRIGHTSIDEBOTTOMCENTERE6 DONE` と1行に詰めて表示され、
上記4箇所のいずれの位置にも一致しなかった(`RESULT: E6_NEGATIVE_CONTROL_OK=true`)。
座標指定を行った場合と行わなかった場合とで表示結果が明確に食い違うことを確認した。

なお、座標指定を一度も行わない検体(マーカー0件)の起動直後の既定カーソル位置は
`(col=0, row=0)` であることも副次的に実測できた(`E6_EMPTY_CONTROL_OK=true`)。

### 文字表示の座標系の範囲

- 実測環境の解像度は 768x512、テキストは 8x16 ドットのANKフォント単位のセルで
  `columns=96, rows=32`(px68kの `readTextScreen()` 診断値。これも実測値であり
  決め打ちではない)。
- **最終列(col=95)・最終行(row=31)はそれぞれ単独では正しく機能する**ことを実測した
  (`RESULT: E6_BOUNDARY_MAXCOL=true`, `E6_BOUNDARY_MAXROW=true`)。
  ただし**画面右下の角そのもの(col=95かつrow=31)は未確定として残す**。理由:
  `main_e6.c` は全マーカー処理後に必ず座標指定なしで `"E6 DONE"` を追記するため、
  右下の角ちょうどに文字を置くと直後の `E6 DONE` 印字が画面末尾を埋めた状態から
  始まり、自動スクロールが起きて直前に置いた文字の行がずれる(=locateの失敗では
  なく、印字が画面右下に達したときの折り返し/スクロールという別の挙動が
  混入する)。これは実際に踏んで切り分けた: 単独実測(`iocs_locate(95,31)` の後
  何も追記しない構成)では正しく右下の角に出ることを確認済みだが、
  `print_at()` API の実装がこの角を単独で(後続印字なしで)使う保証は無いため、
  「角そのもの」は本実測の合格条件には含めていない。

### 範囲外座標を指定したときの挙動

負の値・列/行の上限を大きく超える値(`-1`, `9999`, `-9999` 等)を `iocs_locate()` に
渡しても、**ゲストは暴走せず、その後の座標指定・表示も正常に機能し続けた**
(`RESULT: E6_OOR_SURVIVED=true`, `RESULT: E6_OOR_RECOVER_OK=true`)。

観測された挙動: 範囲外座標を指定した `iocs_locate()` 呼び出しは、**カーソル位置を
一切変更しない(無視される)**。直後の `iocs_print()` はそれまでのカーソル位置から
連続して表示される(範囲外側の軸だけをクリップする、ではなく、呼び出し全体が
無視される)。5件の範囲外呼び出し(`NEGCOL`, `NEGROW`, `BIGCOL`, `BIGROW`, `BOTHNEG`)
がすべて1行に連続して詰まって表示されたことがこれを裏付ける。

範囲を1つだけ超える境界(`col=columns`, `row=rows`)でも同様に無視されることを
確認した(`RESULT: E6_BOUNDARY_MAXCOL/MAXROW` の検証と同じ検体内、`C`/`R`
マーカーの実測)。

**結論として、この学習用 API の要件(「範囲外を無視して落ちない」)は、IOCS $23
自身がすでに満たしている。** `print_at()` の実装側で追加のクリップ処理を入れる
必要はない、というのが今回の実測結果(ただし右下の角ちょうどの単独動作は上記の
理由で未確定)。

## 確定できなかった項目

- **col=columns-1 かつ row=rows-1(画面右下の角)を、後続の印字を一切行わずに
  単独で表示させたときの挙動**は、簡易スクリプトでの単独実測では正常に見えたが、
  `verify/verify_e6.mts` の合格条件には含めていない(上記参照)。`print_at()` API
  が角を最後の呼び出しとして使うケースがあるなら、別途この1点だけを検証する
  必要がある。
- 範囲外座標が本当に「呼び出し全体を無視する」のか、「範囲外の軸だけを何らかの
  形で処理してから無視相当の結果になる」のかは、IOCS $23 内部の実装(IPLROMの
  ファームウェア)までは追っていない。ホスト側から観測できる範囲(カーソル位置が
  変化しない)でしか確認していない。

## 使ったIOCS呼び出し

- `D0=$23, TRAP #15`(候補: B_LOCATE): D1.L=col, D2.L=row でカーソル位置を設定。
  範囲外は無視(実測)。戻り値は未使用(このステージでは読んでいない)。
- `D0=$21, TRAP #15`: 文字列表示(Stage A/Cで実測済み。A1=文字列ポインタ)。

## 構成

- `stage_e/src/main_e6.c`: マーカー配列(col, row, use_locate, text)を順に処理する
  テストプログラム。`use_locate=0` のエントリは `iocs_locate` を呼ばない(陰性対照用)。
- `stage_e/src/iocs_e6.S`: `iocs_locate(int col, int row)` の新規IOCSスタブ。
  D2の退避を含む(上記「確定した座標指定の手段」参照)。
- `tools/gen_markers_e6.py`: マーカー仕様(JSON)から `markers_data.c` を生成。
- `tools/build_stage_e6.sh`: Stage C の crt0/リンカスクリプト/ブートセクタを流用した
  ビルド一式。使い方: `tools/build_stage_e6.sh '[[col,row,use_locate,"text"],...]' out.xdf`
- `verify/verify_e6.mts`: 陰性対照A(マーカー無し)→4箇所実測→陰性対照B(座標指定
  なし)→範囲外座標→境界値、の順に検体を起動し実測する。`no_wait_mode=enabled`
  を最初から設定(未設定だとコアが実時間に自己同期し進まなくなる既知の罠)。
  自前タイムアウト(`makeDeadline`)で暴走時にプロセスごと固まらないようにしている。
