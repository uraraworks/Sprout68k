# wasm-tools Release／GitHub Pages配布手順（2026-08-22）

## 採用方式

約20MBのmemfs版cc1、as、ld、objcopy（JS／wasm各1、計8ファイル）はgitへ
コミットせず、GitHub Release `wasm-tools-v1` のassetとして置く。Linux上でツールチェーンを
毎回再構築する方式は、移植作業とcache miss時の長時間化を避けるため採らない。

`build/web-assets`は約952KiBで、IDEのライブラリ／サンプル変更と同時に更新すべきものなので、
`node tools/update_web_assets_snapshot.mts`で`deploy/web-assets`へ更新し、repoで追跡する。
fresh checkoutではViteがこのsnapshotを使う。

## Release package

```sh
node tools/wasm_release_package.mts --output build/release
shasum -a 256 build/release/sprout68k-wasm-tools-v1.manifest.json
```

出力は決定的なustarをgzip（mtime=0、uid/gid=0、mode=0644、path順固定）したarchiveと、
archive全体および8ファイルのsize／SHA-256を持つsidecar manifestである。取得側は追跡済みの
manifest SHA-256を入口に、archive SHA-256、展開後の全file SHA-256、過不足を検査する。

## リポジトリ作成後にReleaseを作るコマンド

以下はリポジトリとremoteを利用者が作成した後に手で実行する。今回の実装作業では実行しない。

```sh
node tools/wasm_release_package.mts --output build/release
gh release create wasm-tools-v1 build/release/sprout68k-wasm-tools-v1.tar.gz build/release/sprout68k-wasm-tools-v1.manifest.json --title "Sprout68k wasm tools v1" --notes "memfs cc1/as/ld/objcopy"
MANIFEST_SHA=$(shasum -a 256 build/release/sprout68k-wasm-tools-v1.manifest.json | awk '{print $1}')
gh workflow run deploy-pages.yml -f release_base_url="https://github.com/uraraworks/Sprout68k/releases/download/wasm-tools-v1/" -f manifest_sha256="$MANIFEST_SHA"
```

ツールを更新した場合はbasename/tagを`wasm-tools-v2`へ上げ、同じ手順で新しい2assetを作り、
新しいURLとmanifest SHA-256でworkflowを起動する。既存tagのassetを差し替えない。

## ローカル検証

```sh
node tools/verify_wasm_release.mts
node tools/fetch_wasm_release.mts --source build/release --manifest-sha256 <manifest-sha256> --output build/wasm-tools
```

`.github/workflows/deploy-pages.yml`はRelease取得・検証、Vite build、公開物完全性検査、
Pages artifact upload、deployの順に実行する。実際のRelease作成／pushはこのworkflowに含めない。
