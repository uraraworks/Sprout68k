# 共有ランタイムの配布（2026-08-22）

共有リンク `#p1=` を開く側（WebX68k、および Sprout68k 自身）が持つランタイムの配り方。

## 何を配るか

`deploy/runtime/v1/` の3ファイル。合計 5KB。

| ファイル | 中身 |
| --- | --- |
| `runtime.bin` | ランタイム本体（ライブラリ全部入り、4,808 バイト） |
| `boot.bin` | ブートセクタ（248 バイト） |
| `manifest.json` | 大きさ・SHA-256・メモリ配置・ABI 版 |

受け取り側はこの2つのバイナリと、URL から復元した利用者コードを
`tools/share_v1.mts` の `assembleXdf()` に渡すだけで `.xdf` になる。
**受け取り側にコンパイラは要らない。**

## 生成

```
node tools/build_abi.mts            # 生成物を最新にする
node tools/build_runtime_release.mts
```

`tools/verify_runtime.mts` が、
- manifest の SHA-256 と実ファイルが一致すること
- **別の利用者コードでビルドしたランタイムと一致すること**（＝ランタイムが
  利用者コードに依存しないこと。ここが割れると「自分の環境では動くのに
  共有リンクでは動かない」作品ができる）

を確かめる。

## 主体は Sprout68k、受け取り側が持つのは写し

ランタイムを作るのは Sprout68k だけ。WebX68k は写しを持つ。
二重管理に見えるが、**版ごとに凍結された不変のバイナリ**なので更新は発生せず、
増えるだけ。写しが正典と一致することは SHA-256 で機械的に確かめられる。

### 配り方は wasm-tools と同じ「ビルド時取得・実行時は自前配信」

実行時にブラウザから GitHub Release を取りにいく形にはしない。理由:

- **オフライン**: 共有リンクを開いた瞬間にランタイムが要る。外部取得だと
  Service Worker のキャッシュに乗らず、オフラインで開けない
- **CORS**: Release アセットは `objects.githubusercontent.com` へリダイレクトされる。
  ブラウザから取るなら CORS の実測が要る（→ `reference_disk_url_cors_hosts`）
- **可用性**: 共有リンクは永久に動く必要がある。5KB のために外部依存を増やさない

### Release への添付

ABI 版ごとに別タグにする。**過去のタグは消さない**（古い共有リンクが動かなくなる）。

```
gh release create runtime-v1 \
  deploy/runtime/v1/runtime.bin deploy/runtime/v1/boot.bin deploy/runtime/v1/manifest.json \
  --title "Sprout68k shared runtime v1" --notes "共有リンク #p1= の受け取り側が持つランタイム"
```

### 受け取り側（WebX68k）の取得

`tools/fetch_wasm_release.mts` と同じ作法にする。

1. `manifest.json` を取得し、**あらかじめ固定した SHA-256 と突き合わせる**
2. manifest 内の SHA-256 で `runtime.bin` / `boot.bin` を検証する
3. 検証を通ったものだけ配布物へ入れる

取得元は `https://github.com/uraraworks/Sprout68k/releases/download/runtime-v1/` でも、
ローカルの `deploy/runtime/v1/` でもよい（`fetch_wasm_release.mts` の `readSource` と
同じく、http(s) とローカルパスの両方を受ける）。**Sprout68k を公開する前は
ローカルパスで通せる。**

## ABI を増やすとき

1. `runtime/abi_v1.txt` は触らない。**末尾に足すだけ**なら v1 のままでよい
   （既存の番地が動かないため、古い共有リンクも動き続ける）
2. 番地が動く変更をするときだけ v2 を作る。`deploy/runtime/v1/` はそのまま残し、
   `deploy/runtime/v2/` を足す
3. 受け取り側は、ペイロードのヘッダに入っている ABI 版を見て使うランタイムを選ぶ
   （版が無いものは弾く。`unpackUserPayload()` が検査している）
