# 65536色グラフィックとテキストの同時表示可否 実測 20260820

`docs/重なり実測_20260820.md` 項目4への訂正実測。同項目は「65536色グラフィック
モードが有効な間、テキストは一切見えない(排他)」と結論したが、その実験は
`$E80028`(CRTC R20) / `$E82401`(VC R0下位) / `$E82601`(VC R2下位、常に`0x01`固定)
の3つしか振っておらず、VC R2 の値そのものや VC R1(優先度制御、`$E82500`/`$E82501`)
は一度も振っていなかった。直後のパニック画面実装(`docs/パニック画面_20260820.md`)
で `VC_R2=0x20` にするとテキストが見えることが実測され、この帰属が疑わしくなった。
本資料はその再検証。

## 結論(4項目)

| # | 項目 | 確定できたか | 結論 |
|---|---|---|---|
| 1 | 同時に見える設定が存在するか | **確定(存在する)** | **存在する。** 例: `VC_R2下位($E82601)=0x21`(グラフィックページ0有効ビット`0x01`とテキスト表示ビット`0x20`のOR)。VC R1(`$E82500`、優先度制御)は0x00〜0xFF全数を振っても結果は変わらない |
| 2 | 存在するなら設定値 | **確定** | `CRTC_R20=0x08`(既存固定) / `VC_R0=0x03`(既存固定、65536色モード) / **`VC_R2下位=0x21`**(新規判明)。VC R1・VC R2上位は既定値`0x00`のままでよい(後述、例外あり) |
| 3 | 重なった位置での前後関係 | **確定(ただし例外あり)** | **通常はテキストが手前。** グラフィックの塗り色ピクセルの上に、それとは異なる色(グリフのインク)が観測される。VC R2下位が「グラフィック可視かつテキスト可視」となる全124通り、およびVC R1を0x00〜0xFF全数振った256通りすべてでこのパターンが一致した。**例外**: VC R2上位バイト(`$E82600`)を特定の値(`0x14`)にすると、グラフィックの塗りが重畳セル全体を覆い、テキストのインクが見えなくなる(=グラフィックが手前になる)組み合わせが実測で見つかった(後述「Phase Cの例外」) |
| 4 | 存在しないなら振った範囲 | (該当なし、存在した) | 振った範囲は「測定方式」節に明記。VC R2下位・VC R1下位は0x00〜0xFF全数、VC R2上位・VC R1上位は粗く(21点・5点)振った |

**確定できなかった項目**: VC R2上位バイトを全数(0x00〜0xFF)は振っていない(粗く21点のみ)。
このため、VC R2上位の未確認範囲に「同時表示不可」または「グラフィックが手前になる」
別のパターンが存在する可能性は排除できていない。

## 測定方式

`docs/重なり実測_20260820.md`(フェーズ1)で実測済みのピッチ(8ドット/桁、
16ドット/行)・原点(0,0)をそのまま使う(このスクリプトでは再計測しない)。
新規追加した `stage_e/src/main_vc_sweep.c` が、ビルド時に埋め込んだ
`regs[7] = {CRTC_R20, VC_R0上位, VC_R0下位, VC_R1上位, VC_R1下位, VC_R2上位, VC_R2下位}`
を書き込んだ後、同一走査線(桁3行)上に次のセルを配置する:

| セル | 桁,行 | 内容 |
|---|---|---|
| box+text | 5,3 | GVRAM矩形塗り(明色) + IOCS $23/$21で'Z' |
| box-only | 8,3 | GVRAM矩形塗りのみ(対照) |
| text-only | 11,3 | 'Z'のみ(対照) |
| negative | 20,3 | 何も描画しない(検出器の陰性対照、毎回検査) |
| far | 70,3 | 'FAR'(グラフィック面の外側、境界確認用) |
| (別行) | 0,31 | 'ALIVE'(生存確認) |

1設定=1ブートとして、`putImageData`で捕まえたフレームバッファを走査し、機械的に
以下を判定する(目視によらない):

- **グラフィック可視** = box-onlyセルが単色(背景色以外)で塗られている
- **テキスト可視** = text-onlyセルに背景色以外のピクセルがある
- **同時可視(simultaneousVisible)** = グラフィック可視 かつ テキスト可視 かつ
  box+textセルに「box-onlyと同じ塗り色のピクセル」と「それ以外の背景色でない色
  (=グリフのインク)」が両方存在する
- **陰性対照** = negativeセルが背景色のみ(毎設定ごとに検査。全設定でOK)

### 校正(フレーム数)

事前のタイミングテストで、80フレームあれば描画が完了すること(`ALIVE`到達・
セル内容が安定)を実測した。安全係数を掛けて本測定は **`FRAMES=150`** を使用した。

### 振った範囲(このスクリプト自身が決めた。手読みではない)

- **Phase A**: VC R2下位バイト(`$E82601`)を **0x00〜0xFF 全数(256通り)**。
  VC R1=(0x00,0x00)固定、VC R2上位=0x00固定
- **Phase B**: VC R1下位バイト(`$E82500`、優先度制御)を **0x00〜0xFF 全数(256通り)**。
  VC R2下位=0x21固定(Phase Aで「グラフィック・テキストとも可視」だった最小値)
- **Phase C**: VC R2上位バイト(`$E82600`)を粗く(21点: 16刻み9点相当+境界値+
  下記の候補)振った。候補には `px68k-libretro/libretro/windraw.c` の
  `WinDraw_DrawLine()` を読んで見つけたビットパターン(`0x14`,`0x1d`,`0x1e`,
  `0x5c`,`0x5d`。**出所: ソース読解であり実測ではない。実際にどう振る舞うかは
  ここで実測して確認した**)を含めた
- **Phase D**: VC R1上位バイト(`$E82501`)を5点(`0x00,0x0f,0x3f,0xf0,0xff`)粗く

## 実測結果

### 陽性対照・陰性対照(既知の設定の再確認)

| 設定 | グラフィック可視 | テキスト可視 | 期待 | 判定 |
|---|---|---|---|---|
| VC R2下位=`0x01`(Stage B/C/E1既知) | true | false | グラフィックのみ | `VC_POS_CONTROL_GRP_ONLY_OK=true` |
| VC R2下位=`0x20`(パニック画面既知) | false | true | テキストのみ | `VC_POS_CONTROL_TEXT_ONLY_OK=true` |
| VC R2下位=`0x00`(すべて無効) | false | false | どちらも不可視 | `VC_NEGATIVE_CONTROL_OK=true` |
| negativeセル(何も描画しない領域) | - | - | 背景色のみ | 全541設定すべてでOK(異常なし) |

この3件は `docs/重なり実測_20260820.md` と `docs/パニック画面_20260820.md` の
既存の実測結果と一致しており、本測定系が既知の事実を正しく再現できることを
確認した。

### Phase A: VC R2下位バイト全数(0x00〜0xFF)

「グラフィック可視 かつ テキスト可視」だった値は **124通り**:
`0x21`〜`0x2F`, `0x31`〜`0x3F`, `0x61`〜`0x6F`, `0x71`〜`0x7F`, `0xA1`〜`0xAF`,
`0xB1`〜`0xBF`, `0xE1`〜`0xEF`, `0xF1`〜`0xFF`(いずれもビット5(`0x20`、テキスト
表示)が立ち、かつビット0-3(グラフィックページ有効)のいずれかが立っている値。
`0x30`や`0x70`等、ビット0-3が0の値は「グラフィックページ非表示」に該当し候補から
自動的に外れている。これは判定器が機械的にそう判定した結果であり、ビット割当を
先に仮定して絞り込んだものではない)。

**この124通り全てで `simultaneousVisible=true`**(=同時可視の判定も一致)。
代表例(`vc2lo=0x21`):

```
boxOnly    = [["0,231,0", 128]]                          (単色、グラフィックの塗り色のみ)
boxAndText = [["0,231,0", 103], ["231,227,231", 25]]     (塗り色 + 別の色=グリフのインク)
```

塗り色(0,231,0)のピクセルが103個残ったまま、それとは別の色(231,227,231、
テキストの白系インク)が25個追加されている。これは「テキストがグラフィックの上に
重ねて描かれている」ことを示す(セルが単色に潰れておらず、2色が混在している)。

### Phase B: VC R1下位バイト全数(0x00〜0xFF、VC R2下位=0x21固定)

**256通り全てで `simultaneousVisible=true`**、かつ boxOnly/boxAndText の色構成は
Phase Aの`vc2lo=0x21`と完全に同一(`[["0,231,0",128]]` / `[["0,231,0",103],
["231,227,231",25]]`)。**VC R1(優先度制御レジスタ)を全数振っても、この設定
(VC R2下位=0x21、VC R2上位=0x00)における可視性・前後関係は一切変化しなかった**。

`px68k-libretro/libretro/windraw.c` の `WinDraw_DrawLine()` を読むと、
グラフィック(`gon`)・テキスト(`ton`)の描画自体は VC R2 のビットのみで
決まり(`VCReg2[1]&15`、`VCReg2[1]&0x20`)、VC R1(`VCReg1[0]`)は描画順序
(Pri=0〜3のどの段階で描くか)を決めるだけ、という記述になっている
(出所: ソース読解)。実測結果(VC R1を全数振っても結果が変わらない)は、
この読解と矛盾しない。ただしこれは「VC R1が完全に無意味」ということではなく、
**今回の描画順で最終的にテキストが常に一番最後(最前面)に描かれる経路を通って
いた**ためと考えられる(この経路の特定はソース読解によるものであり、
本測定はあくまで「結果が変わらないこと」を実測した)。

### 前後関係の結論

Phase A(124通り)+ Phase B(256通り)= 計380通りの `simultaneousVisible`
設定すべてで、box+textセルに「グラフィックの塗り色」と「それ以外のインク色」が
共存しており、機械的な判定基準(`前後関係の判定`節、`verify_vc_sweep.mts`内)で
全て**「テキストが手前」**に一致した(`VC_FRONT_BACK_DETERMINED=true`)。

### Phase C: VC R2上位バイトを粗く振る(vc2lo=0x21, vc1lo=0x00固定)

21点(`0x00,0x10,0x14,0x1D,0x1E,0x20,0x30,0x40,0x50,0x5C,0x5D,0x60,0x70,0x80,
0x90,0xA0,0xB0,0xC0,0xD0,0xE0,0xF0`)を振った結果、**17点で`simultaneousVisible=true`**、
**4点(`0x14`,`0x1D`,`0x5C`,`0x5D`)で`simultaneousVisible=false`**。

この4点を個別に追加実測したところ(vc2lo=0x21, vc1lo=0x00固定):

| VC R2上位 | box-only | box+text | text-only | 解釈 |
|---|---|---|---|---|
| `0x14` | `(0,227,0)`単色(可視) | `(0,227,0)`単色のみ(**テキストのインクが消えている**) | `(0,0,0)`+`(231,227,231)`(可視) | **例外: グラフィックが重畳位置でテキストを覆い隠す**(テキストは単独では見えるのに、グラフィックと重なる位置でだけ消える) |
| `0x1D` | `(0,0,0)`のみ(グラフィック不可視) | `(0,0,0)`+`(231,227,231)`(テキストのみ見える) | `(0,0,0)`+`(231,227,231)`(可視) | グラフィックがそもそも表示されない設定(排他ではなく、この値ではグラフィック自体が別経路(SP/半輝度合成)に回り単純な塗りが出ない) |
| `0x5C` | 同上 | 同上 | 同上 | 同上 |
| `0x5D` | 同上 | 同上 | 同上 | 同上 |

`0x1D`/`0x5C`/`0x5D` は「グラフィック可視」の判定基準を満たさない(box-onlyが
背景色のみ)ため`simultaneousVisible`の定義上falseになるだけで、テキストは
問題なく見える(排他ではない)。一方 **`0x14`は本測定で見つかった唯一の
真の例外で、グラフィックもテキストも単独では見えるのに、重なる位置でだけ
テキストが消える(=グラフィックが手前になる)**。これは
`px68k-libretro/libretro/windraw.c`の`VCReg2[0]&0x14==0x14`という条件で
分岐する特別な合成パス(ソース上のコメントでは「特別プライオリティ」)に該当する
候補だが、**この特定を裏付けたのはソース読解ではなく上記の実測**である。

`VC_PHASE_C_SWEPT`は21点のみで、VC R2上位バイトの残り235通りは未確認である
(「確定できなかった項目」参照)。

### Phase D: VC R1上位バイトを粗く振る(5点)

`0x00,0x0F,0x3F,0xF0,0xFF`の5点いずれも、グラフィック可視・テキスト可視・
同時可視のパターンが変化しなかった(`VC_PHASE_D_AFFECTS_VISIBILITY=false`)。
`px68k-libretro/libretro/windraw.c`を読むと、VC R1上位バイト(`VCReg1[1]`)は
16色/256色グラフィックモードのパレット選択にのみ使われ、65536色モード
(本測定で使っている`VC_R0=0x03`)の分岐では一度も参照されていない
(出所: ソース読解)。実測結果(5点で変化なし)はこの読解と矛盾しないが、
**全数(0x00〜0xFF)は振っていない**(コスト対効果を踏まえて5点に絞った、
「確定できなかった項目」参照)。

## 陰性対照・陽性対照(まとめ)

- **陰性対照**: 何も描画していないセル(negative、20桁3行)が背景色のみである
  ことを、全541設定すべてで確認した(`negativeCellOk`が全件true)。異常なし。
- **陽性対照1**: VC R2下位=`0x01`(既知の設定)でグラフィックのみ可視 — OK
- **陽性対照2**: VC R2下位=`0x20`(既知の設定)でテキストのみ可視 — OK
- **陰性対照(明示)**: VC R2下位=`0x00`でどちらも不可視 — OK

## 実機/エミュレータの限界(規律の遵守)

**これは px68k(px68k-libretro、WebX68kが使うコア)上の実測であり、実機の
挙動とは限らない。** 実機での確認は行っていない。過去にエミュレータで測った
値がそのエミュレータの実装都合だった実例があり(`docs/重なり実測_20260820.md`
の元の結論自体がその一例)、本資料の「テキストが手前になる」という結論も
px68kの合成ロジック(`WinDraw_DrawLine()`)の実装に強く依存している可能性が
高い。**定性的な結論(同時表示は可能、通常はテキストが手前、特定のVC R2上位
バイトの値で例外がある)のみを採用し、実機での確認は今後の課題とする。**

`px68k-libretro/libretro/windraw.c`のソースを読んで振る対象・候補を絞り込んだ
箇所は、いずれも「ソース読解による候補」であることを明記し、実際にその通りに
振る舞うかは本資料の実測結果(Phase A〜D)で裏付けている。手読みの結果を
そのまま「実測済み」として記録した箇所はない。

## 確定できなかった項目(明記)

- **VC R2上位バイト(`$E82600`)の全数(0x00〜0xFF)は振っていない**(21点の粗い
  サンプルのみ)。Phase Cで見つけた例外(`0x14`)以外にも、未確認の235通りの中に
  別の例外パターンが存在する可能性を排除できていない
- **VC R1上位バイト(`$E82501`)の全数は振っていない**(5点のみ)。ソース読解では
  65536色モードで未使用と読めるが、実測は5点にとどまる
- **VC R2下位バイトとVC R1下位バイトの全組み合わせ(256×256)は振っていない**。
  Phase Aは「VC R1=0固定」、Phase Bは「VC R2下位=0x21固定」でそれぞれ全数を
  振っており、両方を同時に自由に振った場合の組み合わせ全数(65536通り)は
  未実施
- **実機での確認は未実施**(上記「実機/エミュレータの限界」参照)

## 成果物・実行方法

- `stage_e/src/main_vc_sweep.c`: レジスタ値`regs[7]`をビルド時に埋め込み、
  GVRAM矩形塗り+IOCS $23/$21でのテキスト表示を行う検体(新規追加。`lib/`は
  変更していない)
- `tools/gen_regs_vc_sweep.py`, `tools/build_stage_vc_sweep.sh`: 上記のビルド一式
- `verify/verify_vc_sweep.mts`: 陽性対照2件・陰性対照1件・Phase A〜Dの順に実測する

```sh
npx --no-install tsx verify/verify_vc_sweep.mts
```

`WEBX68K_DIR`(既定 `../WebX68k`)、`FRAMES`(既定150、事前校正済み)で上書き可能。
`px68k_no_wait_mode=enabled`を最初から設定している。すべて同期実行、自前
タイムアウト(`makeDeadline`)を使用。全541設定(陽性対照2 + 陰性対照1 +
Phase A 256 + Phase B 256 + Phase C 21 + Phase D 5 = 541、重複あり)を通しで
実行し、`RESULT: VC_PASS=true`(EXIT=0)で完了することを確認済み(2026-08-20実施)。
